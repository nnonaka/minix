# MINIX x86_64 Userland Port — Build Fixes

This document records the fixes applied to build userland and system utilities
for the MINIX x86_64 (amd64) target.

---

## 1. ZFS / osnet disabled for MINIX amd64

**File:** `share/mk/bsd.own.mk`

`MKZFS?= yes` was unconditionally enabled for `MACHINE == "amd64"`, pulling in
the entire `external/cddl/osnet` tree (libavl, libnvpair, libumem, libuutil,
libzfs, libzpool, libctf, libdtrace). MINIX does not support ZFS.

**Fix:** Guard with `!defined(__MINIX)`:
```diff
-.if ${MACHINE} == "amd64"
+.if ${MACHINE} == "amd64" && !defined(__MINIX)
 MKZFS?=    yes
 .endif
```

This reverted all modifications to `external/cddl/osnet/` files that had been
made to work around compilation errors in that tree.

---

## 2. RPC: rpcb_prot.h generated by rpcgen at build time

**File:** `include/rpc/Makefile`

`rpcb_prot.h` is auto-generated from `rpcb_prot.x` via `TOOL_RPCGEN` at build
time. The host's `/bin/rpcgen` is sufficient. No pre-generated copy is needed.
Reverted to the upstream `RPC_INCS= rpcb_prot.h` pattern.

---

## 3. sys/mbuf.h — paddr_t unavailable in userspace

**Root cause:** `paddr_t` is defined in `amd64/types.h` only under
`_KERNEL || _KMEMUSER || _KERNTYPES || _STANDALONE`. Userspace programs
including `sys/mbuf.h` therefore get an "unknown type name 'paddr_t'" error,
which also cascades into a "variable length array in struct" error from
`MBUF_DEFINE(mbuf, MHLEN, MLEN)` because the struct becomes invalid.

**Fix:** MINIX does not support mbuf. Guard `#include <sys/mbuf.h>` with
`#ifndef __minix` in each affected file.

Files fixed:
- `sbin/route/route.c`
- `sbin/route/show.c`
- `sbin/route/rtutil.c`
- `libexec/ld.elf_so/paths.c`
- `external/bsd/tcpdump/dist/print-pfsync.c`
- `usr.bin/netstat/atalk.c`
- `usr.bin/netstat/inet.c`
- `usr.bin/netstat/inet6.c`
- `usr.bin/netstat/unix.c`
- `usr.bin/netstat/route.c`
- `usr.bin/netstat/vtw.c`
- `usr.bin/netstat/pfsync.c`
- `usr.bin/netstat/mbuf.c`

## 4. dhcpcd eloop.c — suseconds_t precision loss

**File:** `external/bsd/dhcpcd/dist/eloop.c:134`

```diff
-tv.tv_usec = ts->tv_nsec / 1000;
+tv.tv_usec = (suseconds_t)(ts->tv_nsec / 1000);
```

`tv_nsec` is `long`; `suseconds_t` is `int` on this target. Clang's
`-Wshorten-64-to-32` treated the implicit narrowing as an error.

---

## 5. binutils — ENABLE_NLS disabled for x86_64

**Files:** `arch/x86_64/config.h` in each of:
- `external/gpl3/binutils/lib/libbfd/`
- `external/gpl3/binutils/lib/libopcodes/`
- `external/gpl3/binutils/usr.bin/common/`
- `external/gpl3/binutils/usr.bin/gas/`
- `external/gpl3/binutils/usr.bin/ld/`

MINIX does not have `dgettext` (gettext/libintl). All five x86_64 config.h
files had `#define ENABLE_NLS 1`; changed to `/* #undef ENABLE_NLS */`.

---

## 6. ld.elf_so map_object.c — inverted __minix guard

**File:** `libexec/ld.elf_so/map_object.c`

`gap_addr` and `gap_size` were declared inside
`#if defined(__minix) && TLS_VARIANT` but used inside `#if !defined(__minix)` —
exactly backwards.

**Fix:** Change declaration guard to `#if !defined(__minix)` to match usage.

---

## 7. MINIX libc stubs

Two symbols referenced by binutils and ld.elf_so are absent from MINIX libc:

### `__msync13` (`minix/lib/libc/sys/msync.c`)
`sys/mman.h` renames `msync` to `__msync13` via `__RENAME`. MINIX mmap does
not cache writes, so msync is a no-op.

### `_lwp_setprivate` (`minix/lib/libc/sys/lwp_setprivate.c`)
Called by `_rtld_tls_initial_allocation` in `ld.elf_so/tls.c` to set the TLS
base (`%fs` register base on x86_64). Full implementation requires either
kernel FSGSBASE support (`CR4.FSGSBASE = 1` + `wrfsbase` instruction) or a
`sysarch` syscall — neither is currently implemented in MINIX. Stubbed as
no-op to satisfy the linker.

Both stubs are wired into `minix/lib/libc/sys/Makefile.inc`.

## 8. usr.bin/make — meta and filemon disabled

**File:** `usr.bin/make/Makefile`

MINIX does not have `fktrace` (ktrace). Setting `USE_FILEMON?= ktrace`
triggered compilation of `filemon_ktrace.c` which referenced `fktrace`.

`meta.c` uses filemon symbols; with filemon disabled its `#ifdef USE_FILEMON`
guards exclude those calls at compile time, but `USE_META` can also be
disabled to avoid stale-object issues.

**Fix:** Set both to `no` by default (overridable):
```makefile
USE_META?=    no      # no filemon support on MINIX
USE_FILEMON?= no
```

Note: `.if defined(__MINIX)` in nbmake Makefiles does **not** work — `__MINIX`
is a C preprocessor symbol, not a make variable. Use unconditional `?=`
defaults instead. See also the **Makefiles — MINIX guards** section in
`CLAUDE.md`.

---

## 9. amd64 stand — legacy BIOS boot excluded

MINIX/amd64 boots via UEFI (EFI bootloader). Legacy BIOS boot components are
not needed and cannot be compiled with the MINIX toolchain (they use 16/32-bit
x86 assembly).

**Files changed:**
- `sys/arch/amd64/stand/Makefile` — removed `mbr` from `SUBDIR`
- `sys/arch/amd64/stand/boot/Makefile` — set `SUBDIR=` (empty, skips `biosboot`)
